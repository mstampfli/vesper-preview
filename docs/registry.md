# Registry: every public function and its tensor contract

This table is the protocol (spec: "the table is the registry"). Before writing a function,
find its row; if there is none, add the row first. Each module has at most ten public functions.
Every contract carries a leading batch dimension `b`. Status: **tested** means implemented with
the test named in the row; **specified** means the row is the agreement and no code exists.

Notation: `n` tokens in the chunk, `d` width, `h` heads, `dk` head width, `C` columns, `T` passes
(`T_max`), `w` window, `k` retrieval count, `V` vocabulary, `M` ledger capacity.

PRIMITIVE `WarmedGraph`, the warm-capture-replay life both drivers share: the first `warm` (`WARM_STEPS` = 3) calls after construction or `reset` run `step(values)` eagerly on a side stream, the next captures it over owned copies of the values (never the caller's tensors) and replays at once, every later call copies its values in and replays (`eager`, `captures`, `replays` counted over its life, a `reset` restarting the warm-up but not the count, so a record tells "ran without a graph" from "never ran"); a value off CUDA is a `ContractError` on every call. PRIMITIVE `GraphFamily`, one `SignatureGraph` per key with every capture in ONE memory pool (`pool` flows to `CapturedStep`'s `torch.cuda.graph(pool=...)`; default None = a graph's own pool, unchanged for every other caller): members never run at once and the caller reads or copies outputs before the next replay of ANY member, so they can share working memory (the instruction preflight of 709df83 ran out of memory with one pool per batch length); `counts()` records each member's captures and replays. PRIMITIVE `memory_peak(device)`: the allocator's peak RESERVATION since `reset_memory_peak` (0 on the CPU), which counts every captured graph's private pool; the peak of allocated bytes does not, since a replay allocates nothing (the 5090 sweep of 2026-10-21 read 0.99 GiB for steps that held 15 GB); every reported memory figure of a GPU run uses it. PRIMITIVE `MemoryPhases`, a run's memory per named phase (maintainer B's design, e919d2d): each phase synchronizes, reads current allocated/reserved, resets both peaks, and at its end reads both peaks, both current values and the family's captures/replays, appending one JSON line as it ends, also on an exception (recorded and re-raised; a failed read is recorded as unreadable and every reading taken before it kept); the counts are the given family's only; phases do not nest and no boundary is inside a capture; `reserved_peak()` is the largest phase reserved peak, the run's `memory_peak` when the phases cover it; allocator statistics, not the smallest card a captured run fits on; nothing empties caches or changes a graph's lifetime. PRIMITIVE `deterministic_algorithms()`, repeatable CUDA training: torch's deterministic algorithms with `warn_only` off inside the block, BOTH previous flags (enabled, warn_only) restored on exit, nested or on an exception; validates its own setup on every entry: a `CUBLAS_WORKSPACE_CONFIG` preset outside `CUBLAS_WORKSPACES` is refused (`RuntimeError`, nothing changed), unset is the measured default; yields the effective settings (both flags, the variable as found, `torch.backends.cuda.cublas_workspace_size()`, and `fill_uninitialized_memory`). Inside, torch's filling of every new tensor with NaN is off (`fill_uninitialized_memory()` reads it, typed; restored on exit): ~2700 fill kernels of a captured step on 2026-10-21, and the two-process repeat test still passes without it. Measured 2026-10-19 (torch 2.14.1+cu130, RTX 5060 Ti): without it two calibration runs with bitwise-equal inputs diverged (real source: update 0 across processes; test size: update 6 in one process), eager and captured, fused or reference scan; with it two fresh processes repeat every parameter and Adam field over 120 updates (capture, warmup end, an evaluation copy) with the variable unset (the committed test), and two processes with `:4096:8` repeated every record and the final weights over 30 updates (an exported probe, not a test), at about 3-8 % per captured update under load. torch substitutes deterministic implementations without raising: the op is not identified and third-party kernels are not certified in general; the guarantee is the measured workload, software and card. ## Decisions recorded here

- The reference scan computes `T = (I + A)^-1 diag(beta)` with an explicit inverse of the
  unit-lower-triangular `I + A` (`torch.inverse`), not `torch.linalg.solve_triangular`: the
  latter is untyped in torch's stubs and would leak `Any` through the whole file. At block 64
  the inverse is exact to 1e-10 in float64 (test).
- Int4 state quantization uses one fp16 scale per state row, not per head: 10.7% vs 15.6%
  round-trip error for 6% more bytes. The spec's original "< 2%" is not reachable with int4;
  int8 reaches 0.9% and is the fallback named in the spec's risk table.
